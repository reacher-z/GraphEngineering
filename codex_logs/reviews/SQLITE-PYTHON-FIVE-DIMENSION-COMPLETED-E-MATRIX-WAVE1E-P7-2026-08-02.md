## Declared contract

Dimensions use the canonical order:

1. `native-affected` (`N`)
2. `changes-affected` (`C`)
3. `total-delta` (`T`)
4. `outer-ledger` (`O`)
5. `cursor-ledger` (`L`)

The Python seam accepts only exact tuples containing two through five exact strings in canonical increasing order. It is
deliberately named and documented as a pair/multi seam. Single dimensions are not claimed by this slice.

Fixed matrix:

- pairs: `N+C`, `N+T`, `N+O`, `N+L`, `C+T`, `C+O`, `C+L`, `T+O`, `T+L`, `O+L`;
- multis: `N+C+T`, `C+O+L`, `N+C+T+L`, `N+C+T+O+L`.

Authentic observations for every selected graph are `B2/N/C/T/L = 1/1/1/1/1`. Selected N/C/T/L projections add one;
O is a separately authenticated mismatch bit. Every projected checker result is rejected with one violation.

## Findings caught before freeze

### Cancellation consumed the evidence arm

Initial handoff occurred before the second cancellation check. A prepared-then-cancelled call deleted S and bound a short-
lived E outcome. The handoff moved after cancellation/release handling. Same-S retry now deterministically selects the
original evidence ticket.

### Competing arms could coexist

Evidence checked release pending, but release did not check evidence pending. Both could attach to one S. The check is now
symmetric, and both arm orders have decisive tests.

### Generic Rule 11 errors could masquerade as count mismatches

An early catch treated every non-O armed error as `rule11-five-count`. A retained-W drift or registration fault could mint a
completed ticket. The accepted implementation creates one local intended count-mismatch object and records a ticket only
when the caught primary is that exact object and the stored projection still verifies.

### Poison-safe A proof was incomplete

Direct adoption-state lookup did not prove identity with the authority-owned context/tombstone/adoption graph. The proof
moved into the outer-authority module and now validates all three registry states and authority pointers by exact identity.

### W validation was temporarily unreachable

An intermediate completed graph helper returned selected W before validating W record/latch/lifecycle. The return was moved
after all checks, and final tests require exact consumed/poisoned W.

### Structured outcome lifecycle could lie

Early selected branches marked T/A poisoned and recorded the completed ticket before outer poison succeeded. Generic errors
left outcome T/A/W marked active after real poison. Final ordering is:

1. W is synchronously marked poisoned when the Rule 11 record is consumed.
2. Authenticated outer poison is attempted while preserving the selected primary.
3. Only successful poison updates pure T/A/reason.
4. Only a successful selected poison records the completed ticket.
5. Poison failure cannot replace the selected primary, create a ticket, or claim false T/A lifecycle.

### Late builtins entered new authentication code

All newly added exact-type/ref/length/integer/tuple/error operations now use stable definition-time aliases. Final added-line
scan found no residual new direct `type/id/ref/len/int/tuple/ValueError` lookup in the authentication paths.
