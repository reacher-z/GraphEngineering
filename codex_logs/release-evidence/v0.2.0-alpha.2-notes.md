# Graph Engineering 0.2.0-alpha.2

Alpha. Public APIs can change. This release adds real execution surface in a few
narrow places and freezes a lot of contract that has no implementation behind it.
The "What is not in this release" section is the more important half of this
document, and the scope limits in "Known limitations" are not softened anywhere.

Python distribution version is `0.2.0a2`; npm packages are `0.2.0-alpha.2`.

## What changed

### Sink-before-write redaction, both languages

A protected journal has no raw append path. TypeScript
`ProtectedJsonlEventStore` consumes only a `PreparedSinkWrite` bound to that
store instance; Python `GuardedJsonlEventStore.write` raises
`UnguardedWriteError` for anything else.

On the durable scheduler path payload protection is mandatory. It fails with
`PAYLOAD_PROTECTION_REQUIRED` before the first event, checkpoint, log, error
payload, temporary plaintext file, or executor invocation. There is no no-op key
provider, no in-process default store, and no fallback to the legacy inline
writer.

### Provider and tool adapters, both languages

- **Mock adapter** — deterministic. Performs no network access, requires no
  credential, reads no clock, spawns no process. Every observable is a function
  of its descriptor, its script, and the request.
- **HTTP adapter** — the transport must be injected. There is no default
  transport and no network fallback.
- **Shell adapter** — always refuses to execute. It imports no
  `child_process`/`subprocess`; there is no code path that runs a process.

### Integrated barrier execution, TypeScript ordinary scheduler

An integrated barrier never enters the ready queue. It is decided by the
scheduler at a quiescence point, with zero executor attempts. See the scope
limit in "Known limitations" — this works in exactly one of the four
language/scheduler combinations.

### GE1421-GE1424 compiler pass and pre-dispatch capability refusal, both languages

- `GE1421_INVALID_BARRIER_POLICY` — claimed policy is not an exact policy object.
- `GE1422_BARRIER_POLICY_KIND_MISMATCH` — shape-exact policy whose `kind`
  disagrees with its threshold members.
- `GE1423_BARRIER_NO_INPUTS` — barrier node has zero incoming edges.
- `GE1424_BARRIER_THRESHOLD_EXCEEDS_INPUTS` — `minimum`/`quorum.accepts` exceeds
  the incoming-edge count.

Diagnostics are emitted in 1421-1422-1423-1424 category order and in node
declaration order within a category. Suppression is local: 1421 suppresses 1422
and 1424 on the same node, 1422 suppresses 1424, and neither suppresses 1423.

Pre-dispatch runtime-capability refusal (`runtime-capability/v1alpha1`) runs in
both languages before any executor, journal, or store operation. This is refusal
based on what a graph *declares*. It is not execution-time enforcement.

### Durable operational CLI commands, both languages

`status`, `inspect`, and `logs` read both journal contracts: `events/v1alpha2`
(protected) and the legacy `events/v1alpha1`. The journal is opened read-only,
`event.data` is never read, and a protected reference is never resolved, so no
key material is required to inspect a protected run. `cancel`, `resume`,
`replay`, `fork`, and `retry` fail closed with a named missing capability rather
than pretending to work.

### Five newly frozen contracts with CI-wired oracles

`approval-semantics`, `durable-extension-semantics`, `isolation-semantics`,
`verification-semantics`, `adapter-semantics`. Each has a case corpus and a
`.validate.mjs` oracle invoked by `pnpm validate:fixtures`, which runs in CI.

Four of the five are explicitly contract-only, carrying `implementationClaim:
false`. Only `adapter-semantics` has native implementations. **A frozen contract
in this repository is not an implemented feature.**

### One complete pattern bundle

`examples/patterns/research-diamond/` — Pattern 01, the multi-source research
diamond. Byte-equivalent JSON and YAML graphs, committed fixtures, and both
TypeScript and Python runners.

## What is not in this release

Every item below is absent, not partial.

- **No isolation runtime.** No isolation provider, capability engine, or merge
  gate. A node executor has the ambient authority of the host process that runs
  it. The `isolation` IR field is refused before dispatch, not enforced.
- **No capability enforcement.** Nothing observes or constrains what a node
  actually does at execution time. Nothing stops a node from performing IO it
  did not declare.
- **No verification, judge, or citation runtime.** `verification-semantics` is a
  frozen contract with `implementationClaim: false`.
- **No budget or cost runtime.** `budget-semantics` is a contract candidate, not
  accepted. `maxCostUsd` is refused as the `cost-budget` capability.
- **No React Explorer and no web UI of any kind.** There is no `.tsx` file in
  the repository.
- **Nine of the ten planned pattern bundles.** One is complete. Of the five
  TypeScript pattern constructors, only `researchDiamond` has a Python peer, and
  `loopUntilDry` is a blueprint no scheduler here runs. Constructed and passed
  to `runGraph`, it compiles and then the run fails before any executor is
  invoked, with `UNSUPPORTED_EDGE_CONDITION` on its `LoopDryVerdict` /
  `LoopContinue` edges (the runtime admits `RouteEquals` on a router and nothing
  else) and `UNSUPPORTED_RUNTIME_CAPABILITY` on `node-kind:validator`. Its own
  doc comment previously claimed the scheduler ignored those conditions and ran
  every round; that was stale and has been corrected.
- **No fourteen-step course.** No course material of any length ships here.
- **No PostgreSQL and no S3 backend.** Local files and same-host SQLite only.
- **No distributed workers.** Single-process async concurrency. Compare-and-swap
  rejects a stale append but is not a lease; there is no multi-host fencing.
- **No provider client.** No OpenAI, Anthropic, or other network client exists.
  Provider-family names are closed enum members of a vocabulary, not
  implementations.
- **No npm package and no PyPI package.** See "Install" below.

## Install

**Neither registry has this release. There is nothing to `npm install` and
nothing to `pip install`.** No package was published under any name for
`0.2.0-alpha.2`, and no name is reserved. Build from source:

```sh
git clone https://github.com/reacher-z/GraphEngineering
cd GraphEngineering
corepack pnpm install --frozen-lockfile
corepack pnpm -r build

# Python
uv sync --project python --extra dev
```

Release tarballs and wheels attached to this release, if any, are build outputs
you can inspect and install locally; they are not registry artifacts and carry
no registry provenance.

### A version divergence this release found, and the hole it exposed

The first packaging rehearsal was red. `check:packed-install` reported:

```
AssertionError [ERR_ASSERTION]: installed CLI reports wrong version
+ actual - expected
+ '0.1.0-alpha.1'
- '0.2.0-alpha.2'
```

Four compiled-in version constants had not moved with the manifests:
`packages/cli/src/cli.ts`, `packages/mcp-server/src/constants.ts`,
`python/src/graph_engineering/cli.py`, and
`python/src/graph_engineering/__init__.py`. All four are now at the release
version and the gate is green.

The Node gate caught its half. **The Python gate did not have that assertion at
all**, so `check-python-artifacts.py` passed while installing a wheel labelled
`0.2.0a2` whose `graph --version` printed `0.1.0-alpha.1`. That check has been
added: the gate now derives the SemVer display spelling from the PEP 440 project
version and requires both the installed console script and the installed
`graph_engineering.__version__` to agree with the artifact label. It was
negative-controlled — with the stale constant restored and the wheel rebuilt,
the gate exits 1 with `installed wheel is labelled '0.2.0a2' but its CLI reports
'0.1.0-alpha.1\n'`.

One version string is deliberately *not* bumped:
`SQLITE_CURSOR_BASELINE_HEADER_CREATION_RUNTIME_VERSION_INTRINSIC`. The
`sqlite-cursor-publication-rebind-v2` contract freezes the creation-runtime
identities as `graph-engineering-typescript@0.1.0-alpha.1` and
`graph-engineering-python@0.1.0a1` and forbids an ambient version there. That is
a wire identity, not a package version.

## Known limitations

These are current, verified against the source at release time. None of them is
softened.

- **`FileCheckpointStore` is entirely unguarded, in both languages.** It imports
  nothing from the redaction layer. A caller who creates a checkpoint with
  application values writes plaintext canonical JSON to disk; only the
  identifiers are hashed, and only into the filename. The mandatory payload
  protection described above covers the durable event journal, not checkpoints.
  The unprotected `JsonlEventStore` and `MemoryEventStore` also remain exported
  public API in both languages.
- **Declared budgets and permissions in the pattern manifest have no
  enforcement.** The research-diamond manifest declares
  `maxProviderCallsPerRun`, `maxCostUsdPerRun`, and `network`/`filesystemWrite`/
  `process` permissions, and marks every one of them `"enforcement": "none"`,
  `"enforcedBy": null`. Those numbers are documentation, not a control. The runs
  perform no network access because the code contains no network call and the
  mock adapter cannot make one — not because a sandbox refused it.
- **`graph status` on a protected journal derives status from event types only,
  so a per-node failure code is not surfaced.** The decoder deliberately drops
  `event.data` and it never reaches any sink; the status projection switches
  solely on `RunStarted`/`RunResumed`/`RunPaused`/`RunSucceeded`/`RunFailed`/
  `RunCancelled`. You can learn that a run failed. You cannot learn from
  `graph status` *why* a particular node failed. `graph inspect` reports
  `attemptFailures` as a count, not a code.
- **Integrated barriers execute only in the ordinary TypeScript scheduler.** The
  durable TypeScript scheduler refuses them because it does not yet journal
  `BarrierSatisfied`. Python executes them nowhere: the Python integrated
  barrier runtime module is imported by nothing but its own test, and the Python
  scheduler refuses any non-trivial barrier config under the generic
  `node-config:barrier` capability name rather than the dedicated
  `integrated-barrier-policy` name TypeScript uses. That naming divergence is
  itself unresolved.
- **Cross-language terminal durable-history interop is unbuildable and is
  skipped with a printed notice.** Under `events/v1alpha2` it needs a transport
  for the protected blobs and a way to admit an externally committed,
  already-guarded history into a guarded store. There is deliberately no such
  adoption door: the TypeScript protected memory store accepts only a
  `PreparedSinkWrite`, and the Python guarded store's legacy path is a rejection
  (`LEGACY_HISTORY_UNSAFE`), not an adoption. Adding one is the single API that
  would let bytes into a guarded store without a guard, so it is an owner
  decision, not a harness fix. The conformance run prints on every execution:

  ```
  OPEN: cross-language terminal durable-history interop is not executed for N
  cases. A guarded store has no way to adopt a foreign committed v1alpha2
  history plus its protected blobs, so neither direction of this harness can be
  built. Nothing else in this run covers one lane consuming the other lane's
  durable history.
  ```

  It is a declared gap, not a silent skip. Nothing else in the suite covers one
  language consuming the other's durable history.

- **No SBOM is attached.** The repository has no SBOM tooling. See the release
  checklist notes; producing one requires adding a generator and pinning its
  output format, which was not done for this release.
