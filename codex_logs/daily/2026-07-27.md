### Independent architecture findings

Three read-only investigations exercised the native APIs and reviewed the
repository dependency graph before implementation:

- TypeScript must publish a leaf `@graph-engineering/sqlite` package rather
  than add SQLite to runtime or persistence. Runtime already depends on
  persistence, so a persistence adapter importing the provider contract would
  create a cycle; putting it in runtime would impose Node-only support on
  every runtime consumer.
- Python can use the standard-library `sqlite3` module in
  `graph_engineering.sqlite_cycle_store`, with every connection owned and
  closed inside a complete synchronous transaction worker.
- Both languages need one public provider-neutral adapter kit for bounded
  capture, validation, canonical operation identity, stored-value recovery,
  ledger result encoding, and descriptor construction. Memory and SQLite must
  consume the same kit; copied private parsing logic is not acceptable.
- The existing 54-case harness is memory-specific. It must accept a provider
  factory, isolated test controls, and cleanup, then run the complete campaign
  independently in TypeScript and Python for both providers.
- Mutations use `BEGIN IMMEDIATE`; ledger retry, migration fence, tail CAS,
  lease fence, business writes, ledger result, and `COMMIT` remain one atomic
  unit. Busy and extended SQLite errors are classified by numeric codes, never
  by driver text.
- Canonical records, checkpoints, and ledger results remain UTF-8 BLOB bytes;
  SQLite never reserializes their JSON. Tenant scope participates in every
  business primary, unique, and foreign key.
- Active WAL databases are backed up through the native SQLite backup API,
  never copied as raw files. Restore is replace-only, invalidates cursors, and
  must pass physical, foreign-key, record-chain, head, checkpoint, ledger, and
  fence audits before publication.
- Crash verification uses actual child processes and forced process death at
  transaction, commit-ambiguity, migration, and backup boundaries. A Worker
  termination alone is not crash evidence.
- The descriptor remains explicit about same-host durability and
  `distributedFencing: false`; S02 does not claim network-filesystem safety,
  distributed consensus, scheduler authority, release readiness, or
  popularity.
